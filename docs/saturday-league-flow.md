# שליפת ליגות שבת — איך זה עובד

## מה קורה כשלוחצים "טען"

### שלב 1 — איסוף רשימת הקבוצות
המערכת לוקחת את `_clubTeams` מהזיכרון (נטען מ-Firebase בהפעלת האתר).  
סינון: רק קבוצות שיש להן `teamId` (מספר מזהה מאתר האיגוד).  
אם אין קבוצות → הודעת שגיאה "יש לסנכרן קבוצות מהאיגוד תחילה".

---

### שלב 2 — בדיקת מטמון ב-Firebase (קריאה אחת)
```
Firebase → teamRoundsCache → {
  [teamId]: {
    rounds: [...],   ← כל סיבובי הקבוצה בכל העונה
    ts: 1234567890   ← מתי נשמר (timestamp)
  }
}
```
המערכת קוראת את **כל** המטמון בפעולה אחת.

**לכל קבוצה בודקת:**
- האם יש רשומה במטמון?
- האם היא טרייה (פחות מ-3 שעות)?

| מצב | פעולה |
|-----|--------|
| מטמון תקף | מסננת את הסיבובים לפי התאריך שנבחר — **מיידי** |
| מטמון ישן / לא קיים | מוסיפה לרשימת הקבוצות לשליפה מהאיגוד |

---

### שלב 3 — שליפה מהאיגוד (רק לקבוצות ישנות)
נשלחת בקשה אחת ל-**שרת Python** ב-Render.com:
```
POST https://chess-manager-7wkr.onrender.com/api/team-rounds-stream
Body: { teams: [קבוצות ישנות בלבד] }
```

השרת:
1. שולח בקשות HTTP **במקביל** לאתר האיגוד — קבוצה אחת = בקשה אחת
2. עבור כל קבוצה — שולף את הדף:
   ```
   https://www.chess.org.il/Tournaments/TeamInTournament.aspx?TeamId=XXX
   ```
3. מנתח את ה-HTML עם BeautifulSoup
4. **שולח את התוצאה לדפדפן ברגע שמסיים** (streaming) — לא מחכה לכולן

---

### שלב 4 — מה מנתחים בדף האיגוד

בדף של כל קבוצה יש טבלאות כאלה:
```
RoundsRepeter_ctl00_GamesGridView  ← סיבוב 1
RoundsRepeter_ctl01_GamesGridView  ← סיבוב 2
...
```

**לכל טבלה מחלצים:**

| שדה | מקור |
|-----|------|
| `matchDate` | תאריך DD/MM/YYYY שמופיע בטבלה (בשורות של כל לוח) |
| `roundNumber` | מספר סיבוב מהכותרת |
| `homeTeam` | שם הקבוצה המארחת |
| `awayTeam` | שם הקבוצה האורחת |
| `homeScore` / `awayScore` | תוצאה (null אם טרם שוחק) |
| `isPlayed` | true רק אם יש תוצאה מספרית |
| `timeSlot` | 15:00 לליגה ג', 10:00 לשאר |

**מבנה HTML עבור משחק שכבר שוחק:**
```
tbody → שורת לוח 1:  "שבת 20/06/2026 | שחקן א | 1 - 0 | שחקן ב"
tbody → שורת לוח 2:  "שבת 20/06/2026 | שחקן ג | 0 - 1 | שחקן ד"
```
← התאריך נמצא בשורות ה-tbody

**מבנה HTML עבור משחק עתידי (טרם שוחק):**
```
tbody → שורות עם שחקנים ותאריך, אבל ללא ניקוד
       OR → tbody ריק (אם הרשימות עדיין לא פורסמו)
```
← אם tbody ריק לגמרי, ייתכן שהתאריך לא יימצא

### שלב 5 — סינון לפי תאריך (בדפדפן)
אחרי שכל הסיבובים חזרו (מהמטמון + מהאיגוד):
```
selectedDate (YYYY-MM-DD)  →  fedDate (DD/MM/YYYY)
מסנן: rounds.filter(r => r.matchDate === fedDate)
```

---

### שלב 6 — שמירה ב-Firebase
```
Firebase → teamRoundsCache → [teamId] → { rounds, ts }  ← מטמון לשימוש עתידי
Firebase → satDates → [YYYY-MM-DD] → { dateDisplay, matches }  ← לתצוגה
```

---

### שלב 7 — תצוגה
מציג את המשחקים לפי שעת משחק (10:00 / 15:00) ולפי חלוקה.  
משחק שטרם שוחק: מציג "טרם" בעמודת התוצאה.

## סטטוסים

| סטטוס | משמעות |
|--------|--------|
| ✅ ok | נמצאו משחקים בתאריך הזה |
| 📅 nodate | לא נמצאו משחקים — הקבוצה לא שיחקה בתאריך זה |
| ❌ fail | שגיאה בשליפה מהאיגוד (timeout / חסימה) |
| ⚡ ממטמון | נטען מ-Firebase — לא נשלחה בקשה לאיגוד |

## הגבלות ידועות

1. **עונה שנסתיימה** — אם קבוצה סיימה את כל סיבוביה, לא יהיו משחקים עתידיים בדף שלה. דף האיגוד פשוט לא מכיל אותם עדיין.

2. **81 קבוצות** — ה-DB הנוכחי מכיל קבוצות מעונות קודמות. לחיצה על **"סנכרן קבוצות מאיגוד"** תוריד למספר הקבוצות הפעילות בעונה הנוכחית (10-15), מה שיאיץ משמעותית את השליפה הראשונה.

3. **Render.com ישן** (free tier) — אחרי 15 דקות ללא שימוש, השרת "נרדם". הבקשה הראשונה לאחר שינה לוקחת 30-60 שניות. מהבקשה השנייה — רגיל.

4. **מטמון 3 שעות** — אחרי 3 שעות, תאריכים נשלפים מחדש מהאיגוד. לתוצאות מעודכנות לפני כן — לחץ "טען" שוב (המטמון מתאפס לקבוצות שלא עודכנו בסיבוב האחרון).
